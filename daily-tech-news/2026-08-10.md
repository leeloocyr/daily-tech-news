## 1. AI / LLM

### ⭐ Agent Plugins 1.0: AI 에이전트 상호운용성 위한 개방형 표준 공개
AWS, Cursor AI, GitHub, Vercel 등 주요 기술 기업들이 협력하여 AI 에이전트의 스킬(Skills) 및 MCP(AI 도구 연동 표준)를 묶어 에이전트 호환성을 높이는 개방형 표준인 "Agent Plugins 1.0"을 공식 발표했습니다. 이 표준은 에이전트가 다양한 외부 서비스 및 도구와 원활하게 통합되고 작업을 수행할 수 있도록 설계되었으며, 에이전트 개발 및 배포의 복잡성을 크게 줄일 것으로 기대됩니다. 개발자들은 플러그인 SDK를 사용하여 커스텀 툴을 쉽게 에이전트 생태계에 연동할 수 있습니다.

**왜 주목할만한가:** ITS 개발자들은 다양한 교통 데이터 소스, 제어 시스템, 외부 서비스(예: 기상 정보, 대중교통 앱)와의 연동이 필요한 ITS 에이전트 개발 시, 이 표준을 활용하여 모듈화된 에이전트 아키텍처를 구축하고 개발 시간을 단축할 수 있습니다.

### ⭐ 월러스, AI 에이전트용 메모리 인프라 공식 출시
월러스(Wallus)가 AI 에이전트가 여러 세션에 걸쳐 지속적으로 정보를 기억하고 활용할 수 있는 '월러스 메모리(Wallus Memory)' 인프라를 공식 출시했습니다. 이 솔루션은 클로드(Claude), 챗GPT(ChatGPT), 제미나이(Gemini) 등 주요 생성형 AI 서비스와 통합 가능하며, 에이전트의 장기 기억력과 대화 연속성을 획기적으로 향상시킵니다. 월러스는 엔터프라이즈 환경에서의 보안 및 데이터 거버넌스를 위한 추가 기능도 제공합니다.

**왜 주목할만한가:** 장시간 운영되며 지속적인 상황 인식이 필요한 ITS 에이전트(예: 교통 관제 에이전트, 돌발 상황 대응 에이전트)에 이 메모리 인프라를 적용하여, 이전 상호작용 및 분석 결과를 기반으로 더 정확하고 일관된 의사결정을 내리도록 지원할 수 있습니다.

### ⭐ 'Orion-120B' 공개: 오픈소스 LLM, MMLU 88.5% 달성하며 강력한 성능 과시
미공개 연구 기관 'Stardust AI Labs'에서 새로운 1200억(120B) 파라미터 규모의 오픈소스 대규모 언어 모델 'Orion-120B'를 Apache 2.0 라이선스로 공개했습니다. 이 모델은 MMLU(Massive Multitask Language Understanding) 벤치마크에서 88.5%, HumanEval 코딩 벤치마크에서 79.2%의 높은 점수를 기록하며, 기존 상용 모델 및 최신 오픈소스 모델들과 어깨를 나란히 하는 성능을 보여주었습니다. 특히, 복잡한 추론 능력과 다국어 이해 능력이 뛰어나다는 평가입니다.

**왜 주목할만한가:** 고성능 LLM을 자체 인프라에 배포하거나 특정 ITS 도메인에 맞게 미세 조정(fine-tuning)하려는 ITS 개발자에게 강력한 대안을 제공합니다. 이는 데이터 프라이버시가 중요하거나 클라우드 비용을 절감해야 하는 ITS 환경에서 특히 유용합니다.

### ⭐ LiteLLM 0.5.x, AI 라우터 기능 강화로 LLM 비용 효율 극대화
LiteLLM의 최신 버전 0.5.x가 출시되며 AI 라우터 기능이 크게 강화되었습니다. 이 버전은 특정 쿼리 및 과제에 가장 적합한 LLM(예: GPT, Claude, 또는 미세 조정된 오픈소스 모델)으로 요청을 자동 분산하여 API 비용을 최대 30%까지 절감할 수 있는 것으로 나타났습니다. 또한, 각 모델의 응답 시간과 성공률을 기반으로 동적 라우팅 결정을 내리는 기능이 추가되어 안정성과 성능 최적화를 동시에 지원합니다.

**왜 주목할만한가:** ITS 시스템은 다양한 유형의 텍스트 처리(예: 도로 정보 분석, 민원 처리, 교통 예측)를 위해 LLM을 활용할 수 있는데, LiteLLM을 통해 각 작업의 중요도와 비용 효율성을 고려한 최적의 LLM 선택 및 운용 전략을 수립하여 시스템 운영 비용을 절감할 수 있습니다.

## 2. 보안 & 취약점

### Critical Cisco ASA/FTD 제로데이 취약점 (CVE-2026-20079) 실제 공격에 악용
시스코(Cisco) 방화벽(ASA 및 FTD 소프트웨어)에서 CVSS 점수 10.0의 치명적인 인증 우회 제로데이 취약점 CVE-2026-20079가 실제 공격에 악용되고 있음이 확인되었습니다. 이 취약점은 원격 공격자가 인증 과정 없이 시스템에 접근하여 임의의 코드를 실행할 수 있도록 허용합니다. 시스코는 8월 1일까지 모든 사용자에게 긴급 패치를 적용할 것을 권고했으며, 아직 패치되지 않은 시스템에 대한 적극적인 스캔 및 악용 시도가 보고되고 있습니다.

**왜 주목할만한가:** ITS 인프라의 핵심 보안 장비인 방화벽의 치명적인 취약점은 전체 교통 시스템의 통제권 탈취 및 데이터 유출로 이어질 수 있습니다. 모든 시스코 ASA/FTD 사용자는 즉시 패치를 적용하고 시스템 무결성을 확인해야 합니다.

### N-central 인증 우회 취약점 (CVE-2026-18577) 실제 악용 확인
N-able N-central 원격 모니터링 및 관리 소프트웨어에서 미공개 상태였던 제로데이 취약점 CVE-2026-18577 (CVSS 8.2)이 실제 공격에 악용되고 있음이 N-able에 의해 확인되었습니다. 이 취약점은 공격자가 특정 API 엔드포인트를 통해 인증 과정을 우회하고 시스템 내부 권한을 획득할 수 있도록 합니다. N-able은 즉시 두 번째 긴급 핫픽스를 배포하고 고객들에게 업데이트를 권고했습니다.

**왜 주목할만한가:** ITS 관리 시스템에서 N-central과 같은 원격 관리 도구를 사용하는 경우, 해당 취약점은 ITS 서버 및 네트워크 장비에 대한 무단 접근 경로를 제공할 수 있습니다. 빠른 패치 적용 및 침해 여부 확인이 필수적입니다.

### 앤트로픽, 클로드(Claude) 원격 코드 실행 "설계대로 작동" 논란 지속
최근 GitHub 이슈를 통해 클로드(Claude) 모델이 특정 프롬프트와 연동된 CI/CD 러너 환경에서 개발자 PC의 명령을 자동으로 실행할 수 있는 잠재적 원격 코드 실행 경로가 공개되었습니다. 앤트로픽(Anthropic)은 이를 취약점이 아닌 "설계대로 작동(as designed)"하는 결과라고 해명했으나, 보안 전문가들 사이에서는 LLM 기반 에이전트의 자율적 코드 실행 능력에 대한 보안 우려가 커지고 있습니다. 특히, GitHub 기반 CI 워크플로우를 사용하는 개발 환경에서 잠재적인 위험 요소로 지적됩니다.

**왜 주목할만한가:** LLM을 활용한 코드 생성 및 자동화 기능을 개발 환경에 통합하는 ITS 개발자들은 이러한 LLM의 자율적 코드 실행 능력과 그에 따른 보안 위험을 면밀히 검토해야 합니다. LLM의 출력을 직접 실행 환경에 연결할 때의 검증 및 샌드박스 정책 수립이 중요합니다.

## 3. 개발 도구 & 프로그래밍

### Cursor AI 코드 에디터, Agent Plugins 1.0 통합 및 로컬 LLM 지원 강화 (버전 0.30.x)
AI 기반 코드 에디터 커서(Cursor AI)가 최신 버전 0.30.x에서 "Agent Plugins 1.0" 표준을 통합하여 개발자들이 에디터 내에서 에이전트의 기능을 더욱 쉽게 활용할 수 있게 되었습니다. 또한, Ollama, GPT4All 등의 로컬 LLM 실행 도구와의 연동을 강화하여, 민감한 코드베이스 작업 시 네트워크 연결 없이도 LLM의 도움을 받을 수 있도록 지원합니다. 코드 자동 완성, 오류 디버깅, 문서화 기능이 크게 개선되었습니다.

**왜 주목할만한가:** ITS 개발자들은 커서를 통해 로컬 환경에서 민감한 ITS 코드(예: 신호 제어 로직, 개인 정보 관련 데이터 처리)를 AI의 도움을 받아 개발, 테스트 및 디버깅할 수 있습니다. 이는 개발 생산성을 높이는 동시에 데이터 보안 및 프라이버시 요구사항을 충족하는 데 도움이 됩니다.

### ⭐ Ollama 2.x 및 GPT4All 1.x, 로컬 LLM 통합 및 에이전트 프레임워크 지원 심화
오픈소스 로컬 LLM 실행 및 관리 도구인 Ollama가 버전 2.x, GPT4All이 버전 1.x로 업데이트되었습니다. 이들 버전은 RAG(Retrieval Augmented Generation) 구성 환경 및 AI 에이전트 개발 프레임워크와의 통합 기능을 심화하여, 개발자가 로컬 환경에서 자체 데이터셋 기반의 LLM 애플리케이션 및 에이전트를 보다 쉽게 구축하고 실행할 수 있도록 지원합니다. 새로운 API 엔드포인트와 컨테이너화 지원으로 배포 용이성도 향상되었습니다.

**왜 주목할만한가:** ITS 개발자들은 Ollama 2.x나 GPT4All 1.x를 사용하여 교통량 예측, 돌발 상황 감지 등 ITS 관련 로컬 모델을 에지 디바이스나 내부 서버에 배포할 수 있습니다. 이는 실시간 응답이 중요하거나 외부 클라우드 의존도를 줄여야 하는 ITS 환경에서 매우 유용합니다.

### GitHub, MCP 및 Agent Plugins 1.0 표준으로 AI 개발 플랫폼 역할 강화
GitHub가 'Agent Plugins 1.0' 표준 개발에 핵심적인 역할을 수행하며, AI 개발 플랫폼으로서의 입지를 더욱 공고히 했습니다. GitHub Actions, GitHub Copilot 등 기존 AI 개발 도구와 더불어, 이번 표준 연동을 통해 다양한 AI 에이전트와 도구가 GitHub 생태계 내에서 더욱 유기적으로 작동할 수 있는 기반을 마련했습니다. 이는 개발자가 AI 기반 워크플로우를 효율적으로 구축하고 관리하는 데 중요한 전환점이 될 것으로 보입니다.

**왜 주목할만한가:** ITS 개발팀은 GitHub를 AI 기반 협업 개발의 중심으로 활용할 수 있습니다. 코드 리포지토리, CI/CD, 프로젝트 관리, 그리고 이제는 AI 에이전트 통합까지 하나의 플랫폼에서 이루어져 개발 생산성 향상 및 팀 간의 효율적인 협업을 지원합니다.

1.  **ITS 시스템에 Agent Plugins 1.0 도입 전략:** ITS 시스템의 다양한 서브 시스템(신호 제어, 돌발 상황 관리, 정보 제공 등)을 AI 에이전트화하고, Agent Plugins 1.0 표준을 활용하여 이들 에이전트 간의 상호운용성을 확보하는 방안 및 로드맵을 논의합니다.
2.  **로컬 LLM (Ollama, GPT4All) 기반 ITS 엣지 컴퓨팅 활용 방안:** ITS 엣지 디바이스(예: CCTV, 센서 허브)에 Ollama 2.x 또는 GPT4All 1.x를 배포하여 실시간 데이터 분석, 이상 감지, 경량화된 AI 추론을 수행하고, 프라이버시 및 응답 속도 요구사항을 충족시키는 방법을 논의합니다.
3.  **LLM 기반 코드 생성 및 검토 도구(Cursor AI)의 ITS 개발 생산성 향상 기여도:** Cursor AI와 같은 LLM 기반 코딩 도구를 ITS 개발 워크플로우에 통합하여 코드 작성, 디버깅, 테스트 케이스 생성 및 코드 리뷰의 효율성을 높일 수 있는 구체적인 방법과 그에 따른 잠재적 이점 및 한계를 분석합니다.
